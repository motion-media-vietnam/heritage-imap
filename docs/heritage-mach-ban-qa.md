# Heritage mách bạn — implementation and acceptance checklist

Source prepared October 25, 2026. **Not release-accepted:** no build, type-check, test execution, rendered-browser QA or PDF regeneration/inspection was performed under this instance's resource policy. Automatically surfaced file diagnostics are not an application build or runtime pass.

## Architecture and reuse

- New route: `/heritage-mach-ban/`; shared `Layout.astro` header/mobile/footer navigation now points here instead of the homepage local-tips anchor. Existing local-tips content remains unchanged.
- Reuse: shared editorial typography/tokens, existing local photographs, `places.ts` identities/facts/coordinates, geographic distance helper and standalone iMap's `openPlace` selection/template/sheet lifecycle.
- `src/data/concierge.ts`: typed editorial collections, concepts, catalog-linked photos and manually curated interest tags. Like existing editorial content modules, this is source-managed TypeScript, not a new CMS or live content feed. A later content-collection migration can preserve its IDs and destination slug references. Editorial text is newly proposed copy; it does not certify businesses or new visitor facts.
- `src/lib/concierge.ts`: bounded deterministic matching, not an LLM or live search. Inferred and selected interests are combined; unavailable interests are disclosed. A mixed request may get explicitly partial suggestions. Special dietary/family/accessibility constraints fail closed because verified suitability data is absent. Arbitrary natural-language understanding is not claimed.
- Time budgets only limit the number of cards (1/2/3/4); mobility is acknowledged but does not infer a navigable route. No hours, visit-duration estimates, journey timings, tickets or certifications are invented. Concept durations are editorial budgets, not verified visit totals.
- Browser coordinates live only in page memory, are requested only on a button click and are never sent to a recommendation backend or placed in a URL/storage. Clear/manual selection/pagehide invalidates pending callbacks and forgets location. The browser's own positioning service is outside application control. Text requests are not sent to a service or persisted by this feature.
- Distances use the existing approximate coordinates and Haversine helper, labeled straight-line, not walking/driving distance. Location ranks results, not an implicit proximity radius; manual areas filter. There is no new map instance on this page.
- `/imap/?place=<canonical slug>` is read once during mounting of `full-imap` only; exact catalog allowlist, unknown/duplicate IDs ignored. Uses the normal story-opening path even when map tiles fail. No URL writing/history listener, filter reset or homepage/prototype deep-link handling is introduced. The embedded homepage and its larger draft/prototype catalog remain separate.
- Photo/video players, galleries, homepage hero and Guide’s Choice, category/cluster/radius/neighborhood controllers and destination records were not changed. Only the standalone production controller's entry selection was extended. Existing workspace edits were preserved.
- Food and people collections, small-alley details and the art itinerary are openly unfinished. Available collections expose real point links; itinerary concepts expose individual point links, never a fabricated multi-stop route.

### Page and accessibility

- Open from desktop and mobile header navigation, footer link, direct URL and browser back. Homepage hero/Guide’s Choice remain visually unchanged.
- Check the static Hồ Gươm hero crop and text contrast, font loading, no video/play button and CTA visibility. The underlying hero/Phố Cổ source photographs were inspected as images, **not** as rendered layouts. Other images reuse existing mappings; rights and final crop approval remain pending.
- Hero CTA focuses the request textarea and scrolls to it. Reduced-motion mode avoids smooth scrolling. Check sticky-header offset and no clipping at narrow/short viewports.
- Prompt strip swipes horizontally without horizontal page overflow; all controls have 48px targets. No nested vertical scroll panels; preferences are initially closed.
- Tab through labels, controls, native details, submit, result heading, clear-filters action and all links; check visible focus. Screen reader gets result counts and permission status without chat bubbles or fabricated live-AI status.
- With JavaScript disabled, static editorial collections and iMap links remain usable; the recommender explicitly requires scripting.
- Verify lazy editorial images, no map/iframe/video loaded on the new page, stable image boxes, failed-image behavior and actual transferred bytes. Hero original is about 0.97 MB; responsive derivatives are not implemented and optimization remains a later asset task.

### Recommendations

- Submit all four example prompts. Hồ Gươm yields canonical Hoàn Kiếm results; vegetarian/coffee returns a truthful empty state; art + relaxation explicitly says art data is missing and only offers relaxation matches; local discovery returns real catalog points.
- Enter Vietnamese/uppercase/plain spelling, a canonical destination, arbitrary unknown text, empty text, long text and HTML-like text (must stay text, never markup).
- Combine manual areas, interests, each time budget and each mobility. Unsupported food/art-only and conflicting filters produce empty states. Selected special requirements and text-based vegetarian/Halal/family/accessibility constraints must not produce unverified recommendations.
- Broaden action resets text, all preference controls and private location, then renders general catalog suggestions. Changing controls alone does not silently refresh an already submitted result; submit again.
- Allow location on HTTPS/localhost; verify nearest-first straight-line distances and clear wording that all catalog points can still be far away. Test denial, timeout, unavailable API, manual area changes and clearing while a location request is pending. No location prompt on initial load, no storage or app recommendation request.
- Submit again after changing location/preferences; check old cards/media disappear, no duplicated results and focus/scroll land at the heading. All result links must be real canonical IDs.

### Map regression — desktop and mobile

- For **each of the six slugs**, open `/imap/?place=<slug>` from a result, collection and applicable itinerary. Verify correct destination title/story and normal mobile sheet. Repeat with slow/failed tile delivery; directory/story fallback must still work.
- Unknown, empty, uppercase, duplicate and HTML-like `place` values should leave the normal map view; unrelated query parameters must not affect state. A bare `/imap/` and the homepage map should behave as before.
- Once linked selection is open: close/reopen, choose a different pin/list item, play available video, browse photos where available, return to the map, resize and use browser back/forward. Check no duplicate player/map/listeners and normal focus restoration.
- Check existing category icons, marker counts/clustering where supported by the existing map, radius/neighborhood/search filters, location permission/denial and reset controls. Do not expect expanded prototype-only destinations on the six-record `/imap/` page.
- Compare desktop story panel/mobile bottom-sheet and map viewport to baseline, including exact camera/filter restoration, touch/pinch/zoom, safe areas and scrolling. No redesign is authorized by this feature.
