## 3. Published vs prototype content gating

- Published mode is the default on both routes. It does not display prominent missing-video or unverified-fact notices. Missing media retains the existing 16:9 illustration frame, with an accessible illustration label, **no `<video>`, player control, media URL or play button**.
- Record publication defaults to draft for new supplementary-content props. A verified asset alone cannot silently publish a draft record. Existing names/coordinates/editorial introductions remain in the legacy sample records and are not migrated or newly declared fully publish-ready.
- Only an explicitly approved publication with verified media can render a video. Guards check destination/city match, destination-specific scope, original-file source, allowed URL form/MIME, actual 16:9 dimensions >=1280×720, positive duration/file size and non-empty source/rights/reviewer approval with valid dates.
- Covers/posters require their **own** verification/rights approval, matching IDs, intrinsic dimensions, alt text and image credit. A verified video never promotes its draft poster. Reviewed credits render only with the corresponding approved image.
- Optional practical prose requires explicit publication approval and verified, dated, non-empty official evidence. The existing dated Văn Miếu prose and editorial tips remain available only in explicit prototype mode until independently approved structured facts are supplied. No new fact, price, opening hour or reference was invented.
- Prototype mode is an explicit component prop, **not** a public query-string override. The frozen isolated `/imap-prototype/` retains its honest labeled notices. Prototype mode still cannot make missing/draft/unverified media playable.
- No real media/covers were provided to the new props, and `dedicatedVideos` remains empty. No general Hanoi overview is attached to any destination. No new catalog, CMS or runtime data loader was added.

These guards validate declared metadata, **not** the truth of footage/rights or availability of a real remote file. Verification remains a human/editorial responsibility. Static Astro gates run at build time: expiry/review dates do not automatically unpublish an already-built page later. A rebuild/unpublish workflow must be agreed before integrating time-limited media.

## 5. Type-check memory investigation

The preceding `astro check` failed at a **256 MB V8 heap** with GC exhaustion/exit 134. That was a failed check, not success. During this phase, cgroup use reached roughly 2.59 GB against 2.68 GB, so simply increasing the heap alongside idle language services would have been unsafe.

Diagnostics identified this session's TypeScript language server and workers (parent matched this harness PID), using roughly 750 MB combined. Only those session-owned TypeScript workers were terminated; other agent sessions/services were not stopped. The existing production preview was stopped before compilation. Explicit tsconfig scopes remove generated QA artifacts from the check without excluding app code, tests or the architecture contract.

After initial cleanup, available headroom was **783,003,648 bytes**. Before the final full rerun, usage was **1,883,340,800 bytes**, leaving **801,013,760 bytes**. Only after these safety checks was the full checker run with a bounded **512 MB heap**, one worker/thread configuration and a 90-second timeout. The final check passed:

```text
Result (40 files):
- 0 errors
- 0 warnings
- 0 hints
```

These combined controls resolved the validation limitation; they do not establish that the broad glob alone caused the old failure. Cgroup OOM counters remained `oom 16`, `oom_kill 4`, unchanged from the start of this work. No old OOM termination is counted as a passing result.
